# راه‌اندازی موتور رسانه‌ای محلی M.R AI با ComfyUI

این اتصال برای اجرای مدل‌ها روی رایانه/سرور تحت کنترل صاحب پروژه طراحی شده است؛ کلید API شرکت تولیدکننده تصویر یا ویدئو لازم ندارد. ComfyUI موتور اجرای گردش‌کار است و خودِ مدل‌های وزن‌باز باید جداگانه با مجوز مناسب نصب شوند.

## تنظیمات سرور

در محیط اجرای `server.mjs` این متغیرها را تنظیم کنید:

- `COMFYUI_URL=http://127.0.0.1:8188`
- `COMFYUI_IMAGE_WORKFLOW=workflows/image_api.json`
- `COMFYUI_VIDEO_WORKFLOW=workflows/video_api.json`
- `COMFYUI_TIMEOUT_MS=900000`

فایل‌های گردش‌کار باید در قالب **API format** صادرشده از ComfyUI باشند. فایل‌های رابط گرافیکی معمولی با این endpoint سازگار نیستند مگر به API format تبدیل شوند.

## جای‌گذاری متغیرها در workflow

در متن مثبت از `{{PROMPT}}`، متن منفی از `{{NEGATIVE_PROMPT}}`، seed از `{{SEED}}`، عرض از `{{WIDTH}}`، ارتفاع از `{{HEIGHT}}`، تعداد فریم از `{{FRAMES}}` و نرخ فریم از `{{FPS}}` استفاده کنید. اگر یک مقدار عددی است، placeholder باید کل مقدار آن فیلد باشد؛ در این حالت عدد به شکل عدد JSON جایگزین می‌شود.

## تصویر

`image_api.json` یک گردش‌کار پایه متداول ComfyUI دارد. نام checkpoint را با فایل مدل تصویر نصب‌شده در پوشه models/checkpoints جایگزین کنید. نام نودها و پشتیبانی مدل‌ها بسته به مدل/نسخه ComfyUI ممکن است فرق کند.

## ویدئو

برای `video_api.json` از یک workflow ویدئویی سازگار با مدل نصب‌شده (مانند workflowهای Wan یا LTX در نسخه/افزونه مربوط) خروجی API بگیرید. placeholderهای بالا را در نودهای متن، ابعاد، فریم و seed قرار دهید. نام نودهای ویدئو استاندارد واحدی ندارند؛ بنابراین فایل workflow باید با مدل نصب‌شده تطبیق داده شود.

## محدودیت‌های شفاف

- این بسته اتصال و مدیریت کار را پیاده‌سازی می‌کند؛ وزن مدل‌ها را داخل ZIP قرار نمی‌دهد.
- کیفیت، مدت و وضوح به مدل و GPU/VRAM وابسته‌اند.
- تا زمانی که ComfyUI، مدل‌ها و دو workflow روی میزبان تنظیم و آزمایش نشوند، تولید واقعی فعال محسوب نمی‌شود.
- endpointها فقط از سرور خود M.R AI به ComfyUI وصل می‌شوند؛ نشانی backend از مرورگر قابل تعیین نیست.
